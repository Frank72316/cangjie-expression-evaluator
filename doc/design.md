# 表达式解析与求值设计

库将源文本转换为带位置的记号，再将记号转换为抽象语法树（AST）。解析成功后才计算数值，因此 `1/0 +` 会先报告末尾缺少操作数。调用方可按错误代码决定如何处理，并使用行列号在原式中标出问题。

## 模块和数据流

| 文件 | 输入 | 输出与职责 |
| --- | --- | --- |
| `src/lexer.cj` | `String` | `Lexer` 实现 `TokenSource` 接口，按需提供下一个记号及其起始位置。 |
| `src/parser.cj` | `TokenSource` | 保留一个前瞻记号，按优先级构建节点表并检查输入末尾。 |
| `src/ast.cj` | 节点和运算符 | `AstNode` 枚举表示字面量、变量、一元取负与二元运算，子节点由整数下标引用。 |
| `src/evaluator.cj` | 节点表、变量快照 | 用 `match` 逐节点求值，提供同步和异步入口。 |
| `src/diagnostic.cj` | 错误代码、位置和原因 | 将各层的失败统一为 `ExprException`。 |

## 文法与结合性

```text
sum     = product { ("+" | "-") product }
product = unary   { ("*" | "/") unary }
unary   = { "-" } primary
primary = number | name | "(" sum ")"
```

每层先取得左操作数，再在循环中组合右操作数。因此 `20 - 5 - 3` 先算 `20 - 5`，乘法层在返回上一层前已经处理完 `*` 和 `/`。连续一元负号只需记录奇偶性。仅括号递归调用 `sum`，进入第 65 层时在左括号处抛出异常。

## 节点存储和求值

以 `2 + 3 * 4` 为例，解析器依次写入以下节点。右操作数的乘法子树在加法节点之前完成。

| 下标 | 节点 | 求值结果 |
| --- | --- | --- |
| 0 | `Literal(2)` | 2 |
| 1 | `Literal(3)` | 3 |
| 2 | `Literal(4)` | 4 |
| 3 | `Binary(Multiply, 1, 2, …)` | 12 |
| 4 | `Binary(Add, 0, 3, …)` | 14 |

每个子节点的编号都小于父节点。一次正向遍历即可从结果数组取出操作数，最后一个节点的值是整式的值。连续加减即使产生很深的左子树，求值阶段的调用栈仍为常数深度。代价是每次求值都分配节点表和等长的结果数组。这个版本每次调用重新解析输入。

## 变量和线程安全

`Evaluator` 持有 `HashMap<String, Float64>`。变量查找使用 `Option` 区分缺失和数值零。`bind` 与快照复制使用同一个 `Mutex`。复制完成后即释放锁，解析和算术运算可以并行执行。异步入口在 `spawn` 之前取快照，因此工作线程何时获得调度不会改变计算结果。

设表达式长度为 `n`、绑定数为 `b`、变量名长度为 `m`。在散列表平均常数次探测的条件下，扫描、解析和求值合计为 `O(n)`，额外空间为 `O(n)`。复用求值器时，时间和空间另加一次 `O(b)` 的变量表复制。`bind` 校验并散列名称的平均时间为 `O(m)`。

## 错误与验证

每个变量和二元运算节点保留源位置。例如 `8/(3-3)` 中，减法正常得到零，除法节点随后在第 2 列报错。多行表达式的 CRLF 只算一个换行。解析、运算和变量绑定都使用同一异常类型。[错误代码表](api.md)

| 测试组 | 用例数 | 检查内容 |
| --- | --- | --- |
| `ArithmeticTests` | 22 | 小数、指数、结合性、64 层括号、1000 项连加及 4001 个一元负号。 |
| `DiagnosticTests` | 38 | 非法字符和数字、缺失操作数、隐式乘法、括号配对、未知变量、溢出和除零。逐例断言错误代码与行列。 |
| `BindingTests` | 14 | 变量更新、非法绑定的回滚、独立实例、32 个在途任务的快照、并发读写与错误传播。 |

独立的 `example` 工程通过 `path = ".."` 依赖库，用于验证公开 API 能在包外调用。两个校验脚本都会构建静态库、运行单元测试，再编译并运行这个示例。
