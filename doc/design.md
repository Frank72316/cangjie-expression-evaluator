# 表达式解析与求值设计

库将源文本转换为带位置的记号，再将记号转换为抽象语法树（AST）。解析成功后才计算数值，因此 `1/0 +` 会先报告末尾缺少操作数。调用方可按错误代码决定如何处理，并使用行列号在原式中标出问题。

## 模块和数据流

| 文件 | 输入 | 输出与职责 |
| --- | --- | --- |
| `src/lexer.cj` | `String` | `Lexer` 实现 `TokenSource` 接口，按需提供下一个记号及其起始位置。 |
| `src/parser.cj` | `TokenSource` | 保留一个前瞻记号，按优先级构建节点表并检查输入末尾。 |
| `src/ast.cj` | 节点和运算符 | `AstNode` 枚举表示字面量、变量、一元取负与二元运算，子节点由整数下标引用。 |
| `src/compiled_expression.cj` | 源文本、变量快照 | 构造时保存解析好的节点表，每次执行用 `match` 遍历节点。 |
| `src/evaluator.cj` | 源文本、变量绑定 | 管理变量和快照，提供直接接受字符串的同步和异步入口。 |
| `src/diagnostic.cj` | 错误代码、位置和原因 | 将各层的失败统一为 `ExprException`。 |

## 文法与结合性

```text
sum     = product { ("+" | "-") product }
product = unary   { ("*" | "/") unary }
unary   = { "-" } power
power   = primary [ "^" unary ]
primary = number | name | "(" sum ")"
```

加减层和乘除层先取得左操作数，再在循环中组合右操作数。因此 `20 - 5 - 3` 先算 `20 - 5`，乘法层在返回上一层前已经处理完 `*` 和 `/`。连续一元负号只需记录奇偶性。仅括号递归调用 `sum`，进入第 65 层时在左括号处抛出异常。

遇到 `^` 时，解析器暂存底数节点、运算符位置及指数开头负号的奇偶性。读完整条幂链后，从右向左生成节点。例如 `2^-3^2` 先生成 `3^2`，再对这个指数取负，最后生成底数为 2 的幂。每个 `^` 只入表和取出一次，临时空间与幂链长度成正比，长幂链不增加递归深度。

## 节点存储和求值

以 `2 + 3 * 4` 为例，解析器依次写入以下节点。右操作数的乘法子树在加法节点之前完成。

| 下标 | 节点 | 求值结果 |
| --- | --- | --- |
| 0 | `Literal(2)` | 2 |
| 1 | `Literal(3)` | 3 |
| 2 | `Literal(4)` | 4 |
| 3 | `Binary(Multiply, 1, 2, …)` | 12 |
| 4 | `Binary(Add, 0, 3, …)` | 14 |

每个子节点的编号都小于父节点。一次正向遍历即可从结果数组取出操作数，最后一个节点的值是整式的值。连续加减即使产生很深的左子树，求值阶段的调用栈仍为常数深度。

`CompiledExpression` 独占解析器生成的节点表，构造结束后只读。对于含 `k` 个节点的公式，多次执行共享这 `k` 个节点，每次单独分配 `k` 个结果槽。不同任务可以并行写入各自的中间值。调用方决定公式对象的生命周期。接受字符串的接口每次构造并执行一个临时公式，两种入口使用同一套求值和错误定位代码。

## 变量和线程安全

`Evaluator` 持有 `HashMap<String, Float64>`。变量查找使用 `Option` 区分缺失和数值零。`bind` 与快照复制使用同一个 `Mutex`。复制完成后即释放锁，解析和算术运算可以并行执行。异步入口在 `spawn` 之前取快照，因此工作线程何时获得调度不会改变计算结果。

设表达式长度为 `n`、绑定数为 `b`、变量名长度为 `m`。在散列表平均常数次探测的条件下，扫描、解析和求值合计为 `O(n)`，额外空间为 `O(n)`。复用求值器时，时间和空间另加一次 `O(b)` 的变量表复制。`bind` 校验并散列名称的平均时间为 `O(m)`。

`bindAll` 与单项写入及快照共用同一把锁。在锁内复制当前变量表，依次校验输入并写入副本，最后一次性替换原表。中途抛出异常时，副本随调用结束而丢弃。两个写入者会基于前一次提交后的表工作，所以更新不同变量时也能保留双方的结果。

非空批次需要复制已有的 `b` 个绑定，并在锁内校验与写入整批数据。变量表较大时，这项开销也会延长其他读写者等待锁的时间。单项 `bind` 可以直接在锁内更新一个键。

查询变量时，`variableNames` 扫描已有节点表。解析器按源文本顺序写入变量叶节点，因此即便幂运算从右向左结合，也能按出现顺序收集变量。哈希集合负责去重，列表记录顺序。只有调用查询接口才进行这次扫描。`missingVariables` 先收集名称，再持有求值器的锁一次，逐项检查键是否存在。这样并发的 `bindAll` 要么已经完整生效，要么尚未生效。查询只探测公式涉及的键，额外存储与不同变量名的数量成正比。

## 错误与验证

每个变量和二元运算节点保留源位置。例如 `8/(3-3)` 中，减法正常得到零，除法节点随后在第 2 列报错。多行表达式的 CRLF 只算一个换行。解析、运算和变量绑定都使用同一异常类型。[错误代码表](api.md)

| --- | --- | --- |

| `DiagnosticTests` | 38 | 非法字符和数字、缺失操作数、隐式乘法、括号配对、未知变量、溢出和除零。逐例断言错误代码与行列。 |
| `BindingTests` | 14 | 变量更新、非法绑定的回滚、独立实例、32 个在途任务的快照、并发读写与错误传播。 |
| `CompiledExpressionTests` | 9 | 构造期诊断、运行期错误后的复用、跨求值器并发、异步快照以及与字符串接口的结果对照。 |
| `PowerTests` | 17 | 幂链的右结合、负号、实数定义域和溢出、10,000 个连续幂运算符，以及编译公式的异步快照和错误恢复。 |
